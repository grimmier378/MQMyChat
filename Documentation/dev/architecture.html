Per-Frame: imanim context (OnUpdateImGui, MQMyChat.cpp:202)

On the first in-game frame, OnUpdateImGui() creates the plugin-owned imanim context (s_iamCtx = iam_context_create(), lines 209-214) with iam_set_lazy_init(false), then each frame makes it current around the render pass (iam_context_set_current, line 217) and restores the previous context afterward (line 228). It does NOT call iam_update_begin_frame() — the host drives imanim's shared clock. This powers the myui styled widgets in Core/Widgets.cpp.
The imanim context (s_iamCtx) is a plugin-owned animation state machine that persists across frames and is shared with the Core/Widgets styled-widget library. The host (MQ's ImGui integration) drives the global clock, so MQMyChat must not call iam_update_begin_frame(). Instead, MQMyChat sets the context as current for the duration of the render pass, allowing the widgets to queue animations, and then restores the previous context so the host continues its work uninterrupted.

Thread Safety Notes

No explicit synchronization (mutex/lock) in any module. All MQ callbacks (OnIncomingChat, OnWriteChatColor, OnUpdateImGui, OnPulse) run on the MQ main thread. Database protected by SQLite WAL mode; transactions used for batch writes. m_claimedLines accessed in ProcessIncomingChat and CleanExpiredClaims (both main thread). BlechCallback is synchronous during Feed() call. ConsoleWidget may have internal synchronization.
