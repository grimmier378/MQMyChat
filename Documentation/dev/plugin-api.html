Plugin API

Last Updated: 2026-06-11

MQMyChat exports a C++ interface (MyChatAPI.h) so other native MacroQuest plugins can route text into MyChat channels and query channel state without going through the macro/Lua TLO layer. The interface is obtained at runtime via MacroQuest's standard GetPluginInterface() mechanism — the same pattern used by MQ2Nav, MQ2Lua, and other community plugins.

This is the C++ plugin-to-plugin API. For macro/Lua access, see the TLO page (${MyChat}).

Interface Definition

The exported interface lives in MyChatAPI.h under namespace mqmychat. The header is dependency-light—only needs <mq/Plugin.h>—so a consuming plugin can copy it into its own tree and include directly. No linking against MQMyChat is required; the interface resolves at runtime.

ChatAPI Methods

GetAPIVersion int GetAPIVersion() const Returns MQMYCHAT_API_VERSION. Always call this first to version-guard the interface.

Clear void Clear(std::string_view channel) Clears a channel's console buffer. Empty string or "main" clears the main console.

Consumer Usage Example

Minimal pattern for another plugin sending colored text into a MyChat channel:

#include "MyChatAPI.h"  // vendored copy

static mqmychat::ChatAPI* s_chat = nullptr;

PLUGIN_API void InitializePlugin()
{
    s_chat = mqmychat::GetChatAPI();
}

void NotifyAlert()
{
    if (!s_chat || s_chat->GetAPIVersion() != mqmychat::MQMYCHAT_API_VERSION)
        return;  // MQMyChat not loaded or built against different API

    // Auto-creates "Alerts" if missing, prints in red.
    s_chat->Send("Alerts", "Rare spawn incoming!", MQColor(255, 0, 0));

    // Default-color convenience overload.
    s_chat->Send("Status", "MyPlugin ready");

    // Direct main console output.
    s_chat->SendToMain("Plugin online");
}

Design Notes

Why bypass Blech: Programmatic output from plugins is already final—it should not be re-pattern-matched, re-filtered, or deduped against the claimed-lines map. The API is a direct console append.

Why ephemeral channels: Auto-created channels keep producer-plugin output out of the user's saved presets. A /mychat reload or plugin unload removes them.

ABI stability: ChatAPI is pure-abstract. Adding new methods to the end of the vtable keeps old consumers binary-compatible. Bump MQMYCHAT_API_VERSION and document the change when the vtable shifts.

Plugin name: Always use mq::GetPluginInterface("MQMyChat"); the name must match the DLL base name.
